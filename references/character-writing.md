# 怎么把人物写活

这一页只写原则和检查方法，不给人物、台词、场景的样例：样例会被照抄（`ideation.md` 开头）。文中「TA」指任何一个重点角色，「主角」指玩家操控的那个人；性别、人数都从构思来。

玩家记住一个角色，靠的是 TA 和别人不一样的地方、TA 自己的矛盾、TA 做的小动作。人设表写得再全，台词里没有这些，角色还是死的。故事要有戏，还得知道 TA 想要什么、缺什么、什么毛病会惹出冲突。

数字后面括号里标性质：原文 / 摘要 / 实测 / 推算 / 估计（没有出处的经验值）。出处是作者整理的一份 galgame 设计调研，没有随仓库发布。

## 1. 人设

### 1.1 人物表

SPEC 里每个重点角色写一张。必填的五行让故事推得动；可选的按构思挑，不是每个角色都要原型、反差、秘密：

| 项 | 必填 | 写什么 | 怎么检查 |
|---|---|---|---|
| 年龄 | ✓ | 数字，同步写进 `CAST` 的 `age`；可攻略角色默认 18 岁以上（SKILL 红线） | 和立绘、台词的年龄感对得上 |
| 想要 | ✓ | TA 嘴上追的目标，能写上白板 | 具体到一件事、一个时间、一个地方 |
| 缺 | ✓ | TA 真正缺的；故事结束时得到、失去或认清 | 和「想要」不是一回事 |
| 缺陷 | ✓ | 会引出冲突的毛病 | 能推出一场冲突；萌点不算缺陷 |
| 说话 | ✓ | 写进声音卡（§2） | 遮住名字认得出 |
| 主题 | | TA 这条线回答全作的哪个问题 | 换个角色来回答，答案应该不一样 |
| 弧光 | | 起点 → 终点；也可以不变，变的是主角对 TA 的理解 | 终点是 TA 自己走到的，或者故事说清了为什么没走到 |
| 原型 | | 一个词，让玩家一眼认出 | 全作不重复 |
| 反差 | | TA 身上和原型矛盾的一面，从「缺」里长出来 | 说得出来由；全作不重复同一个维度 |
| 秘密 | | 揭开的那件事 | 揭开时改变了玩家对前面某场戏的理解 |
| 基线 | | 平时情绪开几成；什么让 TA 破功 | 破功的点和别人不同 |
| 变化落在哪 | | 结局时的变化落在一个行动、一个选择、一段关系、一句话、一个习惯里 | 全作的重点角色不用同一种；对照 `defaults-check.md` |
| 小动作 | | 2–3 个，旁白里写 | 只有 TA 会这么做 |
| 招牌姿势 | | 2–3 个 `pose` | 和别人的不撞 |
| 喜欢 / 讨厌 | | 各 1–2 个具体的东西 | 能在剧情里用上 |
| 专属 | | 场景、配乐、颜色、道具 | 颜色和剪影不撞 |
| 表情 | | 3 个「情境 → 表情」，按 TA 的性格，不按情境的常见反应 | 至少一个是意料之外的反应 |

- 每一格都从构思里来：构思选中的那个起点（手艺、地方、关系、问题、玩法、讲法）决定了这个人能长成什么样
- 换皮测试：把 TA 挪进另一个题材的故事，人设还原样成立，就是太通用
- 依据：写作指南都把目标、缺陷放在原型前面；只抄原型的行为、不写动机，是角色写坏的主因（概括 + 摘要）

### 1.2 差异化检查

人物表填完先过这张表，再写剧本 v0：

| 轴 | 规则 |
|---|---|
| 和主角的关系 | 重点角色之间不重复 |
| 缺（TA 需要什么） | 不重复 |
| 说话节奏 | 不重复 |
| 主题色、招牌姿势、发型 | 颜色和剪影不撞 |
| 原型、反差（写了的话） | 不重复，反差维度全作最多一次 |
| 变化落在哪 | 不重复 |
| 换皮测试 | 每个人都挪不进别的故事 |

### 1.3 主角

没有默认型，跟着构思选：

| 型 | 是什么 | 什么时候选 |
|---|---|---|
| A 代入 | 无立绘、少台词、可改名；性格靠选项，独白克制 | 玩家想当自己；选择本身是看点 |
| B 有性格的观察者 | 固定名，独白有态度 | 故事靠主角的眼睛和判断讲 |
| C 强个性 | 主角自己有一条变化的线或一个谜 | 主角的变化就是主线 |

- 主角在故事里靠什么动起来，从构思来：一个本事、一个处境、一个秘密、一个目标，挑最贴这个故事的一个
- 主角卡写进 SPEC「核心设定」：名字（或不写）、靠什么动起来、外部处境、视角（第一人称、第三人称、多视角，从构思来）、声音卡、有无立绘、配不配音
- 能动性
  - 故事里至少一次只有主角能做的决定，选了有后果
  - 主角的处境和重点角色的「缺」咬合：主角能给的正好是 TA 缺的，或者正好给不了，冲突从这来
  - 选项写主角会说的话、会做的事，不写态度标签；别排成「积极 / 中间 / 消极」三档
  - 主角说出口的台词一章不少于 8%（估计；A 型可以更少）

### 1.4 配角

- 有就给功能，挑 2–3 个：吐槽或装傻、推主角一把、暗示关系到了哪、带出世界规则、自己有一件小事
- 不抢重点角色的戏；至少一场和重点角色有来有回，不只围着主角转
- 外部压力：从构思的人物和地方里来，和 TA 的缺陷叠在一起；不默认用期限（`defaults-check.md`）
- 多人场面：4 人以上时，在场的人 8 行内至少开口一次，不然让 TA 下场（估计）

## 2. 台词

### 声音卡和呼称表

并行写的时候最容易走样的是口吻和称呼，主角独白最先露馅。SPEC 里每个说话角色一张声音卡（主角、旁白也要），全作一张呼称表；子 agent 照它写，审读照它查。

```
### <说话人 id> <名字>
- 自称 / 叫主角 / 叫别人：<…>（会随关系变的写「→ 何时变」）
- 句尾和语气词：爱用 <…>；不用 <…>
- 口癖：<一句，或没有>，一章 ≤ <N> 次，只在 <什么情况> 说
- 省略号：<多 / 少 / 不用>，只在 <什么时候> 用
- 绝不说：<…>
- 样本台词（按本作现写，平时 / 被说中 / 动真情各一句）
```

呼称表：行是说话的人，列是被叫的人；会随关系变的写「→ 何时变」。

- 声音卡的每一格都按本作现写；别的游戏的声音卡不拿来当参考
- 口癖可以没有；有就少而准，一章 ≤ 3 次

### 怎么写

- 一句话只干一件事。长解释拆成两三句，中间插一句旁白写动作
- 同一个意思，每个角色说法不一样。写完把名字遮住读一遍，分不出谁在说话就是没写好
- 少写「我很生气」「我很开心」：让表情、动作、一句只有 TA 会说的话来说
- 对白要有来回：一个人说完，另一个人接一句反应（吐槽、追问、沉默也算）；同一个人连说不超过 4 行
- 同屏的重点角色之间要有关系，不只是轮流对着主角说
- 不写说明台词：角色别把双方都知道的事说给对方听
- 省略号：带「……」的行一章 ≤ 15%（估计）；每人用多少写进声音卡
- 搞笑写成三拍：铺垫 → 偏一步的回答 → 点破；定好谁装傻谁吐槽
- 中文
  - 不写翻译腔（默认禁用正则见 spec-template §2 `LINT`）；人设需要的在 SPEC 写豁免
  - 不用网络流行语
  - 不写「不是 X，而是 Y」这种空对比，旁白不升华

## 3. 旁白

旁白是谁、站在哪，跟着 SPEC 的视角走：第一人称就是主角的内心，第三人称是一个有态度的叙述者，多视角就每段说清是谁。

- 写看到的具体细节，少写形容词；细节要是这个地方、这个人才有的
- 每次角色登场，至少写一个具体的小动作或物件
- 旁白有性格，一次一句，别抢戏
- 占比：对话场景旁白 ≤ 35%，连续旁白 ≤ 3 行（估计）
  - 独处、回忆不限占比，但连续 6 行内要被外界打断一次
- 不写画面已有的：表情换了就别写「笑了」，音效响了就别写「门响了」
- 写画面给不了的：细微变化、动作背后的信息、判断
- 台词能带出的动作不另写旁白

## 4. 演出：用好引擎给的表现手段

画面会动的地方都要用上，这是代码画的角色显得生动的关键；用多了又会把视线从文字上拉走。用量参照商业作的实测：

| 手段 | 写法 | 什么时候用 | 用量 |
|---|---|---|---|
| 表情 | 台词第 3 项 | 说话前换，跟着人物表「表情」那行走；嘴上逞强时台词和表情可以不一致 | 同一人约 2–3 句换一次（实测）；每句都换显得神经质 |
| 表情符号 | 第 4 项写表情符号名 | 轻松的瞬间 | 喜剧场面 6–8 行一个，严肃场面不用（估计） |
| 姿势 | `{ pose }`，站位 `"<id>:<表情>#<姿势>"` | 用人物表里的招牌姿势；情绪转折时换 | 每人 3–4 句最多换一次（估计） |
| 一次性动作 | `{ act }` | 同意、否认、惊喜、害怕、道谢 | 一个场景两三次 |
| 旁白里的动作 | `{ who: "<id>", pose }` | 旁白写某人的动作，同一行让 TA 真的动 | 无 |
| 两人同屏 | 节点 `stage: { l, r }` | 对峙、一个说一个听 | 不说话的人别一直站着；三人同屏只在热闹场面 |
| 进出场 | `stage` 加 `enter` / `exit` | 跑进来、跑掉；同一人换位置会自动滑过去 | 无 |
| 画外音 | 第 4 项 `"off"` | 人不在画面里 | 无 |
| 换装 | `stage` 里写 `@<服装>`，或台词选项 `{ outfit }` | 场合变了 | 无 |
| 时段 | 节点 `tod` | 跟着剧情的时间走 | 无 |
| 转场 | 节点 `trans` | 不写就按默认溶解；时间跳跃、回忆进出、闭眼睁眼各有对应的 | 默认溶解已经够（实测：商业作 90% 的换景带转场） |
| 震屏、闪白 | 台词第 4 项 `{ fx }` | 落在描写冲击的旁白行（实测 80%） | 震屏每章 1–3 次，闪白每章最多 1–2 次（估计） |
| 文字节奏 | 文本里 `{w}` `{slow}` `{big}` `{red}` `{shake}` | 停顿、结巴、关键的一个词 | 每章 3–6 处（估计） |
| CG | 场景用 `cg_` 开头的 | 剧情最关键的那一刻；位置跟着本作的弧形走 | 一章最多一张 |

表情对照：`neutral` 普通、`smile` 微笑、`grin` 大笑、`shy` 害羞、`pout` 嘟嘴、`angry` 生气、`sad` 难过、`cry` 哭、`surprise` 惊讶、`smug` 得意。

### 声音

- 曲目按本作的情绪地图定：先列全作会出现的几种情绪和几个只属于某人、某地的时刻，各配一首；一般 8–12 首（估计）。曲名、乐器、几首，都从本作来，别照上一个游戏的曲目表排
- 换曲：情绪转折才换，换场景不换；一首至少撑 20–30 行（实测中位 32 行）
- 静音：每章至少一段 `bgm: "none"`，放在真相揭开前、关键一句前、坏消息之后；静音时配环境音
  - 回忆、独白压低音乐用 `bgmVol: 0.5`
- 环境音 `amb` 交代「在哪」，可以顶替 BGM；`weather: "rain"` 会自动接雨声
- 音效：每 100 行 3–8 个（估计），只放在希望玩家注意到的瞬间
- validate 会提醒：一章平均不到 15 行就换一次 BGM、整章没有 `bgm: "none"`

## 5. 弧形、选项和数值

### 5.1 弧形

每章（或每条线）先选弧形，再分场。同一游戏里的几条线，弧形不全一样：

| 弧形 | 走法 | 这种弧形自己的要点 |
|---|---|---|
| 慢热 → 暗转 → 回收 | 先写日常，再暗转，最后用前面埋下的东西推一把 | 暗转要让人失去点什么；危机来自前面埋好的缺陷或秘密 |
| 中点确认 → 危机 | 关系或目标在中点就达成，后半写达成之后的危机 | 危机是达成带来的，不是外面掉下来的 |
| 对手 → 同盟 | 开头立场相反，中间被迫合作，最后各让一步 | 两边都有道理；让的那一步各自付出代价 |
| 秘密揭开 | TA 的秘密是故事的机关；每一场都在靠近它 | 揭开前每场都留一点违和；揭开后回头看说得通 |
| 倒着讲 | 从结果开始，回头讲怎么走到这一步 | 玩家知道结果，悬念放在「为什么」上 |
| 一个晚上 | 时间压得很短，靠场景和对白的密度推 | 场景少、转折多；不靠时间跳跃 |
| 没有转折 | 一件事慢慢做完，变化在细节里 | 每场一个小的新东西；短章、日常适用 |

不管哪种弧形，都守：

- 伏笔最晚在这一章（这条线）的前半埋完；每个伏笔登记进伏笔表
- 高潮、转折的解法必须是前文出现过的台词、道具、线索；不许新出现的外力、巧合、超自然救场（依据：读者讨厌没铺垫的「miracle turns」，原文）
- 结局形状照 `genres.md`「结局的形状」挑

### 5.2 选项和数值

- 选择点放在角色被逼着反应的瞬间，流程性的动作不问（原文）
- 每个选择点 2–3 个选项；选完 1–3 行内看得出被回应
- 选项要有真分歧：两个都说得过去，选哪个取决于玩家怎么理解这个人、这件事
- 选项照本作的主要互动写（`genres.md`「互动」）；下面的类型和配额是主要互动为「分好感」时的口径，别的互动按 SPEC 自定：

| 类型 | 怎么加分 | 用在哪 | 配额（估计） |
|---|---|---|---|
| 偏向型 | 每个选项给不同的人加分，没有错答 | 多人共处的段落 | 多人段落 ≥ 一半 |
| 理解型 | 懂 TA 的加分，没那么懂的 0 或少加；错的也说得过去 | 单人段落 | ≤ 一半 |
| 表达型 | 0 分；台词、表情、表情符号必须不同 | 都可 | 每章 ≤ 1/3 |
| 关键型 | `set` flag，后面一定要读（validate 查写了没读） | 转折 | 每章 1–2 个 |
| 限时型 | `timer` 5–10 秒（摘要）+ `timeout` 写沉默、犹豫的后果 | 故事里真有时间压力的时刻 | 0–2 个；不默认放在定线或高潮 |

- 数值口径（全 skill 只认这一处，SPEC 只写本作的例外）
  - 选项每次 +1 或 +2；只有关键剧情节点的 `add` 可以 +3
  - 扣分最多 −1
  - 多人段落一个选择点只动 1–2 个人
- 加分的理由要能用 TA 的「缺」解释，审读会对照查
- 回应「刚才选了哪项」的台词按那个选项 `set` 的 `f_` 分，不按数值分（spec-template §1）

## 6. 写完自查

- [ ] 遮住名字读一段对话，能分出谁在说话；每人的自称、称呼、口癖和声音卡对得上
- [ ] 每个重点角色都有一个让人记住的瞬间，而且这个瞬间挪不进别的故事
- [ ] 每个场景至少有一处表情变化、一处姿势或动作；旁白说的动作和姿势对得上
- [ ] 同屏的人有互动，不只是轮流对着主角说
- [ ] 主角的选项写的是主角会说、会做的事；说出口的台词比例照 §1.3
- [ ] 对话场景旁白 ≤ 35%，带「……」的行 ≤ 15%
- [ ] 解法前文埋过；弧形自己的要点做到了
- [ ] 每章至少一段静音；换曲跟着情绪走
- [ ] 对照 `defaults-check.md` 过一遍，命中的说得出非要不可的理由
