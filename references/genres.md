# 结构

结构跟着构思走（`ideation.md`），不跟着题材词走：同样说「恋爱」，可以是三个人的分院帽，也可以是一个人一整晚的单线。下面是引擎现在撑得住的几种，没有默认；构思里写了别的形状，照构思来，引擎不够就先改引擎。

括号里标性质：原文 / 摘要 / 实测 / 推算 / 估计（出处是作者整理的一份 galgame 设计调研，没有随仓库发布）。

## 所有结构都守

- 不卡关：数值不够永远有出口（进别的结局，或带着低数值往下走）
  - `end: { type: "retry" }` 只给剧情里明确的失败，重来前告诉玩家错在哪；validate 查到「数值比较后面直接 retry」会提醒
  - 依据：章末卡数值的商业作，章节通过率逐章掉、差评集中在卡关（实测 + 原文）
- 开场要快：第一章开头约 40 句内出第一个选择（`LINT.firstChoice`）；100 次点击内出钩子（摘要）
- 每章一个情感落点，同一游戏里不重复；剧本 v0 的结构图里每章写一句
- 进哪条路由玩家刚做的选择决定：判定写「最后选了什么（flag）+ 数值够不够」，不只比数值

## 几种形状

| 形状 | 是什么 | 适合 | 系统 |
|---|---|---|---|
| 单线多结局 | 只有一条路，结局由一路上的几个决定组合出来 | 一个重点角色，或没有恋爱 | flag 为主，数值可选 |
| 短章 | 很多短章，每章一个小事件，结局看几个关系值的组合 | 日常、群像 | 几个关系值，选项多数只改台词 |
| 线索 | 每章查一件事、拿几条线索；最后用线索开选项 | 悬疑、推理 | `CLUES` + `need` |
| 循环 | 每章一轮，失败重来，线索跨轮保留 | 同一段时间反复看 | `CLUES` + `retry` |
| 自选 | hub 页让玩家决定先去哪、找谁 | 地点多、顺序无所谓的故事 | `FLOW` 的 `{ pick: [...] }` |
| 分院帽 | 共通段 → 判定 → 分成几条线，各自收尾 | 2–3 个重点角色，各有一条完整的路 | 每人一个数值 + 定线的 flag |
| 梯子 | 主干一章章往下走，每章末一个出口，不满足就继续 | 3 个以上重点角色，每人一段结局 | 同上；出口条件同样是「选了 + 够不够」 |

几种可以拼：分院帽的共通段用自选，线索型里加一个人的数值。表里的顺序没有推荐的意思。

### 各形状的写法

- 单线多结局：一路上的决定各 `set` 一个 `g_` flag；最后一章的章末 `branch` 按 flag 组合分结局，最后一项兜底
- 短章：`FLOW` 按顺序列很多章；每章一个关系值的小变化；最后一章按几个值的组合（`a>=3`、`a>b`）分结局
- 线索：节点或选项 `clue: "<id>"` 发线索，`R.CLUES` 登记（`ch` 是首次能拿到的章）；决定性的选项写 `need: ["<线索>"]`；真相和默认时间轴写进 SPEC，所有章节共用；每条关键线索至少一条必经路径能拿到
- 循环：失败写 `end: { type: "retry" }`，回到章首快照（数值和 `g_` flag 回滚，线索保留）；重来前告诉玩家错在哪；写清什么情况下回档、谁保留记忆、哪个角色是「常数」（每轮一字不差）
- 自选：`FLOW` 里写 `{ pick: ["ch2", "ch3"], title, desc }`，玩家在 hub 页挑顺序；各章不能依赖彼此的先后，要依赖就用 flag 判断
- 分院帽：共通段章末 `branch`，每项「最后选了谁（flag）+ 那人数值够不够」，最后一项兜底；进线的节点写一段过渡，再 `end: { type: "chapter", id: "<章>" }`；分出去的章不写进 `FLOW`，但要登记在 `R.CHAPTERS`
  ```js
  branch: [
    { need: ["f_pickA", "a>=5"], next: "c1_toA" },
    { need: ["f_pickB", "b>=5"], next: "c1_toB" },
    { next: "c1_other" },
  ]
  ```
- 梯子：每章末 `branch` 一个出口（「选了 + 够不够」进结局章），兜底接下一章

`solve.js --endings` 对所有形状都能验结局走不走得到；有数值判定的再用 `--vars`、`--odds` 定门槛（SKILL 第 7 步）。

### 真结局（看过别的结局才开）

- 引擎还不支持「看过哪些结局」当条件；用户要，先说明，改成别的形状或先改引擎

## 结局的形状

不默认「每条线 Good / Normal + 一个 Bad」。按构思挑：

| 形状 | 是什么 |
|---|---|
| 分好坏 | 同一条线，做到了 / 没做到 |
| 分方向 | 几个结局都成立，差在主角选了什么价值 |
| 余味 | 事件结局一样，关系或人物的状态不同 |
| 开放 | 停在一个决定之前，玩家自己补 |

- 坏结局是玩家选择的直接后果，不专门为了进坏结局设一个罚分选项（原文）
- 结局数跟着结构走，不凑整数

## 互动

「选一句话说」只是一种。构思时想清楚玩家反复做的那件事，选项就按它写：

- 说什么、不说什么（沉默也是一个选项：限时 + `timeout`）
- 给出什么：一样东西、一条线索、一个秘密
- 相信谁、站谁那边
- 去哪、先找谁（`pick` 或选项）
- 记住什么、忘掉什么（flag 跨章）
- 交换：拿一样换一样（两个数值此消彼长）

引擎写法都是 `choices` + `add` / `set` / `clue` / `need`；要新的交互（拖拽、输入、地图）先改引擎。

## 规模

- 一条路 15–25 分钟；中文约 3–4 万字一小时（估计）
- 节点：一章 25–40（估计）；分院帽的共通段每多一个重点角色 +6–8，分出去的线每条 25–35（估计）
- 重点角色 2–3 个是上限，多了用梯子（原文：同人作者说路线三条是极限）
- 分院帽里，单周目的共通段占 1/3–2/3，单条线是共通段的 0.75–2 倍（推算）

## 场景

- 选代码画得出来的：场景少、反复用；靠对话推进，不靠动作戏
- 场景从构思的地方里来：这个地方独有的那几处，而不是「这类故事一般会有的地方」
